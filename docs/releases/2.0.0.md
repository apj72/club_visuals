# Club Visuals 2.0.0 — current interface becomes the default

The current redesigned editor and all recent development are promoted to `main`.
This release is the continuation of `ui/redesign-v1-skin`, not the earlier,
incomplete `feature/ui-v2` Studio trial. That trial is superseded and retained
only as historical work; do not merge it over the current application.

## Start and update

Save open playlists and Show Builder drafts before updating. With the live output
stopped, update your checkout to `main`, then run `./stop.sh` and `./start.sh`.
Open http://localhost:8008/ and refresh any iPad/output/FX/VFX windows.
`python3 server.py` provides the same complete app in the foreground; `--port`
and `--bind` are supported. The old redesign launcher remains compatible.

## Routes

| URL | Behaviour |
| --- | --- |
| `/` and `/index.html` | Current complete editor |
| `/#playlist`, `/#builder` | Direct workspace links |
| `/redesign`, `/redesign/` | Redirect to `/`, preserving query and fragment |
| `/classic`, `/classic/` | Classic editor with shared runtime data |
| `/?host=1` | Resident Mac engine; presentation scripts are excluded |
| `/output`, `/effects`, `/vfx` | Existing output/controller documents |
| `/api/show-library` | Shared Show Builder library, available from normal startup |
| `/api/app-info` | Startup identity and application version |

## GitHub and rollback

`main` remains the repository default branch. Use feature branches and pull
requests for new work. `v2.0.0` marks the promoted release. The tags
`pre-default-ui-2026-11-19` and `pre-default-main-2026-11-19` preserve, respectively,
the complete application immediately before promotion and the older `main`.
Development and release promotion preserve Git history without force-pushing.

For a quick interface fallback, visit `/classic`. For a full code rollback,
stop the app and use a separate checkout/worktree of `pre-default-ui-2026-11-19`,
then run its `python3 ui-redesign/launch.py` command. Keep your runtime folders
backed up and deliberately point the rollback installation at the same source
media. Run only one writable installation against the same metadata at a time.
Do not use `git reset --hard` over local changes.

## Data

No migration or renaming of videos, playlists, cue ranges, presets, catalogue,
configuration or show models is required. These remain in their existing paths
and stay outside Git. Browser preferences retain their existing origin and keys.

## Validation

Route tests cover standard/compatibility startup handlers, classic and engine
HTML, preserved bookmark parameters, complete assets and iPad links. Shared
show-library persistence/concurrency tests and the existing Python/JavaScript
suites cover the backend and playback components. Browser checks exercise
homepage workspaces, playlist preview, iPad links and compatibility redirects
against isolated documentation data. Physical live inputs/output require a
venue rehearsal; automated checks do not connect a camera or microphone.

## Editable showcase source fix

The ripple and colour/trails examples now use their original footage with live
effects. Their old rendered MP4s contained three panels inside a single frame,
which made layout counts appear incorrect. The originals remain available; the
local repair backs up affected playlists/models and retains layout choices and
duration. Save any open browser drafts, then reload the corrected playlist.
